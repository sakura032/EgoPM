## 五、重要经验 / 坑（接手务必知道）

1. **代理陷阱**：若 `HTTP_PROXY`/`HTTPS_PROXY` 指向已关闭的本地代理端口，Python `urllib` 全部请求会连接失败（表现为 `service_transport_exhausted`、`http_status: None`），而 `curl` 却通。诊断：`python -c "import urllib.request; print(urllib.request.urlopen('https://dashscope.aliyuncs.com',timeout=10).status)"`。生产**不用代理、直连**即可。
2. **TPM 预留池模型行为与公共池 alias 不同**（已弃用预留池）：预留快照要求 messages 含 "json" 字样、且需显式约束顶层 `{"items":[...]}` 与 `p` 嵌套，否则返回裸数组/扁平三元组。公共池 alias 无此问题。
3. **公共池吞吐上限**：新账号公共池 alias 稳定约 **26–34 包/分钟**；调并发 4→7 几乎无效（瓶颈在账号/服务端配额，不在并发）。单请求延迟呈"快慢锯齿"（0.4s 与 7s 交替），疑服务端排队，跨账号/通道一致，本地无法根治。
4. **内容审查误报**：口语字幕触发 `data_inspection_failed` → `content_filtered`，属正常损耗，最终记 `excluded_content_filtered`。
5. **误重跑会污染 progress/run_state**：对已完成 Wave 误跑 `--realtime-execute` 会把 progress 踩成 `preparing_source`/清零，可用 `--close-realtime-wave-coverage` 重跑恢复；不要手改 JSONL。
6. **断点续跑幂等**：`--realtime-execute` 同 run 重复执行会自动跳过已 validated、修复 needs_item_audit、重发未完成包；瞬断包不写账本故重发不撞“重复 request id”。若遇冲突，必须由确定性迁移工具原子重建相关 package/Wave/累计账本并保留全部 usage/费用事件；禁止手改或删除 JSONL 行。
